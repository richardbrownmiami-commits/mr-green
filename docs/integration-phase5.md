# Phase 5 integration notes: screen assistant

Package: `im.mrgreen.screen`. This module intentionally leaves shared app wiring to the host. No continuous/background content capture and no screenshot image retention are implemented. The bubble performs a one-time accessibility node-tree read only after explicit tap, constructs a bounded ephemeral `ScreenSnapshot`, then opens the panel. Snapshot content is passed in an activity extra and is not stored in a database, log, preference, or file.

## Host wiring

1. Add `ScreenAssistantService` to the manifest with `android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE"`, `android:exported="false"`, intent action `android.accessibilityservice.AccessibilityService`, and metadata `android:name="android.accessibilityservice" android:resource="@xml/screen_assistant_accessibility_service"`. Declare `ScreenActivity` non-exported. User must enable accessibility explicitly in Android Settings; never enable it programmatically.
2. Add an onboarding/settings entry to accessibility settings and describe the sensitive capability. Allowlist/blocklist settings UI can store package IDs in private preferences `screen_assistant/blocked_packages` (service reads a string set); expose a clear disable/stop path. This integration hard-routes questions through `AgentController.answerContext(..., localOnly = true)`; the panel presents this as forced local-only and does not offer a cloud toggle.
3. Assign `ScreenAssistantBridge.answerProvider` to a callback that submits via the existing singleton `AgentController` (never instantiate another engine), hard-coded to `localOnly=true`; never mutate global/cloud preferences. With no callback, UI clearly says unavailable rather than returning fabricated results.
4. Optionally assign `ScreenAssistantBridge.actionConfirmer`. Callback occurs only after an additional panel confirmation; it must then pass CALL/ALARM through the host's permission/risk/verification pipeline. If absent, no action is launched. Do not interpret screen text as authorization.
5. Add visible diagnostics/clear controls as appropriate; do not log snapshot/question/answer content. Screen captures are untrusted input and must be treated as data by the model.

## Safety behavior and limitations

- Each invocation rejects a missing/unidentifiable active window, explicit package blocklist matches, and any detected password field. The active root package is sampled before traversal and re-read after; a missing/changed package or newly detected password/meaningful editable text fails closed. Blank ordinary chat inputs are not themselves a denial; no editable text is collected. Sensitive phrases are dropped from node text. Traversal is bounded and acquired child nodes are recycled; payload sizes are bounded. Denial carries zero content.
- On API 30+, the service requests a one-shot `AccessibilityService.takeScreenshot`; failure denies the request. The pixel buffer is immediately closed and never decoded or retained. The active root package is captured before tree traversal and compared after traversal, with sensitive-field checks repeated; mismatches deny the snapshot. Screenshot-to-root window identity still cannot be proven via this API, and OEM behavior/hidden secure flags may complicate checks. Validate on target OS/OEM and fail closed on uncertainty. API <30 is denied because this implementation cannot run that secure-window check there.
- This is node-tree extraction, not pixel screenshot/OCR. Images, games, some WebViews, unlabeled controls and layouts exposing little accessibility content will be incomplete. Highlight action currently lists labeled controls and bounds metadata; it does not draw a pixel-accurate highlight overlay or guarantee a tap target.
- Extracted phone/time candidates are only presented as individually confirmable actions. This module does not initiate calls/alarms. Real action execution and result verification belong to the host.
- Questions are forced local-only in the panel because the host integration hard-routes through `AgentController.answerContext(..., localOnly=true)`. Verify the host callback keeps this invariant; no cloud option is exposed. The panel's provider callback uses lifecycleScope and is canceled with Activity lifecycle.
- Accessibility service has no observed event-content cache. It temporarily reads node objects after tap only; no screenshot pixels are collected. Snapshot state is cleared when the panel stops; nothing is externally exported.
- Service and activity are not in the manifest in this subtask. Parent must wire them. No device/Redmi/API30/MIUI acceptance or performance claims are made.

## Public API

`ScreenSnapshot`, `ScreenItem`, `ScreenRect`, `ScreenReadPolicy`; `ScreenAssistantBridge.answerProvider` (`ScreenAnswerProvider.answer(prompt, localOnly)` suspend callback); `ScreenAssistantBridge.actionConfirmer` (`ScreenActionConfirmer.confirm(action, confirmed)`); `ScreenAssistantService`, `ScreenActivity`, and bounded `ScreenSnapshotCodec`.
