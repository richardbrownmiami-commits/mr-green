# Safe local actions in Mr Green 0.10.5

Mr Green now has more useful **offline, APK-owned operations**, without adding a shell or a second backend. Existing chats, notes, model preferences, app identity and database version are retained. SkillBot is not part of this change.

## Try these in chat

| Request | What actually happens |
|---|---|
| `free storage` or `storage status` | Reads free/total space on the app-data volume. It does not browse files. |
| `model status` | Reports whether the one local GGUF is loaded, not its private filename/path. |
| `redacted diagnostics` | Reports app version, Android API, primary ABI, available memory and a model-loaded flag. It does not read/export logs, messages, environment variables or credentials. |
| `search apps calculator` or `find apps camera` | Searches launchable installed apps, returning at most ten label/package matches. Android package visibility still applies. |
| `search notes groceries` or `find notes bicycle` | Searches existing private notes only, with literal `%`, `_` and backslash handling. Returns at most ten short excerpts. |
| `check notes` | Shows up to twenty short private-note excerpts, with a bounded total response. Saved notes are not truncated or deleted. |

Existing battery, time/date/math, notes, alarm/timer, media, app and settings actions remain. `storage settings` still opens Android's storage settings; it is separate from the new storage reading. Opening another app/settings/Clock is a **handoff**, not verified completion. Media and notification handlers were reused rather than duplicated. No contacts/calendar permissions or duplicate media handlers were added.

## What enforces safety

The Kotlin tool registry is a fixed allowlist with declared argument types and permission metadata. Unknown IDs, extra arguments, missing arguments, invalid times, out-of-range durations and oversized plans fail closed. Plans are copied before waiting for the serialized execution lock. All steps are validated before the first action; cancellation is checked again immediately before dispatch. Runtime permissions are checked by the APK, not granted by the assistant.

Plans have at most 16 steps, a 16,384-character serialized input budget and a 12-second cooperative dispatch budget. Native responses are bounded. These limits do **not** make an already-blocked synchronous Android/Binder call interruptible. A stopped plan does not undo earlier actions.

There is no shell/Bash/root operation, generic broadcast/intent operation, arbitrary path reader, environment/secrets reader, package installer/uninstaller, or delete/overwrite note tool. New note saves use new private filenames and preserve the existing file-plus-database readback behavior. No cloud tool planner was added.

## Optional manual screen controls

These controls are deliberately **manual**, not generated by the GGUF. For the Redmi's Android 11, use a personal build and separately accept **Capability setup → Enable personal-use screen reading**. Normal builds keep this feature blocked. On Android 34+ the existing screen-reader secure-capture path remains; the new manual control session is currently limited to the personal-use Android 11–13 path rather than weakening that policy.

Open **All capabilities → Confirmed app recipes**, enable the Recipes accessibility service if needed, and tap **Start manual controls**. Switch to a harmless app, then tap **Controls** in the overlay. Available operations are a bounded local visible-tree view, exact-label tap, one scroll or short vertical swipe, text entry in a uniquely labeled empty field, Back, and Home. Text is entered only from this form, never from chat/model output. Entering text does not automatically press Send/Save, though the target app itself may process or sync input.

Every mutation needs an explicit one-action confirmation. The target package, window, session generation, age and ephemeral tree fingerprint are rechecked after confirmation. Ambiguous targets, password/nonempty editable fields, sensitive labels, blocked apps, changed screens and oversized/slow trees fail closed. Known settings/install/payment/authentication/browser/external-AI/terminal apps are blocked, and the user's existing screen blocklist is honored. These package/label checks are conservative heuristics, not proof that every sensitive app or translated label can be identified.

The visible **STOP** bar cancels pending confirmations and future steps, dismisses controls, and stops the screen reader/local generation. A screen-reader **Read / STOP** strip is also provided. Restart the screen-reader accessibility service after stopping it. Manual sessions expire after five minutes or forty action attempts; each confirmation expires after thirty seconds. Stop cannot undo a submitted action or guarantee cancellation of a gesture already accepted by Android. Existing WhatsApp and Wi-Fi recipes now also require a working Stop overlay, bounded traversal, cancellation checkpoints and honest handoff messages. Existing message text is not overwritten; delivery remains unverified.

**Android 11 cannot reliably establish whether a window is protected.** The personal-use consent does not fix that platform limitation. Use only harmless screens. Screen text/tree fingerprints are ephemeral, not stored or exported. Live model chat and screen answers still use only the local GGUF; unavailable local inference never switches to cloud.

## What remains unverified

There is still **no integrated GGUF tool-call loop**. Deterministic rules, explicit validated routines and manual controls are the supported action selectors. A model's prose cannot execute a tool or shell command. No claim is made about Redmi installation, MIUI survival, third-party layout compatibility, accessibility gesture effects or model-selected actions without owner-device logs.

This implementation adapts design patterns only. No ClawDroid source code was copied, so no copied-code MIT notice is needed. Existing third-party notices remain unchanged.

## Installation safety

Version code 14 keeps application ID `im.mrgreen`, target API 30 and ARMv7-only packaging. Debug APKs use this builder's development key, not an owner release key. Compare certificates before installing over an existing app. If Android rejects the signature, **do not uninstall or clear data**: an in-place update needs the original signing key. Uninstall/reinstall erases private data and may require reimporting the GGUF. An unsigned release APK is not directly installable.

Exact final build, test, lint, ABI and signing results are recorded in [the validation notes](safe-local-actions-validation.md).
