# Phase 8 knowledge integration

Package: `im.mrgreen.knowledge`.

## Implemented API and host behavior

- Construct `KnowledgeRuntime(context, greenStore)`; call `suspend execute(request): String?` on the host coroutine queue. Supported forms: `search web <query>`, `fetch <https-url>`, `ask documents <query>` / `search documents <query>`, and `recipe save <name> | <https-url> | <description>`. This module does not call an LLM; document search returns quoted passages/instructions.
- `KnowledgeActivity` has an `ACTION_OPEN_DOCUMENT` picker, asynchronous import, progress display, and cancel control. If the static activity runtime was lost after process death, it resolves `((application as GreenApp).roadmap.knowledge)` and restores the static reference. The launcher still needs to ensure `RoadmapRuntime.connect()` or equivalent is invoked for app-wide wiring.
- `importUri` indexes TXT/MD/CSV/JSON/text-PDF/EPUB/SQLite into existing `rag_docs` and `rag_chunks`; source cap 16 MiB, extracted output cap 3 MiB, bounded EPUB entries/per-entry bytes. PDF extraction loops pages and stops at output cap instead of joining unbounded page text. Database inserts remain transactional. `progress` and `cancelImport()` are exposed.
- `localOnly=true` blocks web and MCP network calls. MCP server configuration is persisted only after explicit approval. `initializeMcp(serverId, approved)` and `listMcpTools(serverId, approved)` issue bounded JSON-RPC calls; `callMcp` also requires per-call approval, server/tool allowlisting, and `localOnly=false`. MCP args default-deny unless caller explicitly sets `mcpArgsReviewedPublic=true` and `mcpArgsOrigin="user-typed-public"`; typed-secret detection and `GatewayRedactor` unchanged-output checks reject suspect values. Host must show destination, method/tool, and complete args for each review; approval cannot be inferred from server setup.
- `recipes()` returns saved recipes. Recipes do not auto-run. SQLite import uses read-only SQLiteDatabase and fixed table/row caps; there is no SQL query interface or text-to-SQL.
- Network endpoints are HTTPS-only; redirects are not followed; resolved loopback, private, link-local, multicast, IPv4 and IPv6 ULA addresses are rejected. Bodies/timeouts are bounded. Search uses DuckDuckGo HTML, validates extracted URLs, and provides links only; user must explicitly `fetch` a chosen result to obtain source text/citation. Fetched content is marked untrusted. Recipes may be saved/reused only by an explicit save request and remain inert.

## Host wiring / dependencies

No shared core, manifest, or build files were changed. Host should add internet permission if absent, instantiate the runtime alongside `GreenStore`, expose `KnowledgeActivity` through existing navigation/manifest wiring, and route requests before AI. For RAG answer generation, host may pass returned passages as ephemeral context to existing `AgentController.answerContext(..., localOnly=true, category="rag")`; there is deliberately no second model engine and the runtime does not invoke that callback itself. PDF support requires app dependency `com.tom-roush:pdfbox-android:2.0.27.0`; optional Jsoup dependency is not required by current parser.

## Security limits and outstanding gaps

- No user-facing MCP configuration/review panel exists here: caller must render server destination, tool and exact arguments and set the explicit public-typed provenance gate only after review. Current provenance is a host-set runtime flag, not cryptographically bound to an argument object; host must reset it on every call and must not use this path for data from documents, model output, contacts, notifications, or other unknown sources. `GatewayRedactor` is a heuristic, not a proof of privacy. P2/private args are rejected, never silently sent.
- RAG currently does not invoke AgentController callback, and retrieval citations identify chunk labels rather than true PDF page/EPUB section for all chunk boundaries; explicit source-page/section metadata preservation, stopword/light stemming, and RAG callback handoff remain to be implemented. Import currently materializes bounded full extracted text and chunks before DB write; although hard-capped, it is not true streaming/chunk-batch processing. Cancellation does not interrupt a read already blocked in a content provider.
- Web top-result fetch-and-answer/citation flow is not automated; user must explicitly fetch a selected URL. Recipe save is explicit and recipes are inert; no execution engine is provided.
- DNS rebinding remains possible because Java URL resolves independently after preflight validation; production needs pinned-address transport or a robust network policy. Search markup can change. MCP supports bounded initialize/list/call JSON-RPC over HTTPS but not SSE, OAuth, or streaming. Remote results are untrusted data, never instructions.
- UI remains a lightweight entry/import screen; it does not provide an auditable MCP tool review/configuration flow or web source selection panel. No Gradle build or device acceptance validation was run by instruction.
